UI Lab initialization IDs, schema 2

Framing is <unpadded Base64URL binary>_<eight lowercase hexadecimal CRC32 digits>. The CRC covers the binary bytes. It detects accidental corruption, not authenticity. No network, filesystem paths, generated CSS, templates, comments, property names, or executable functions are serialized. The decoder also accepts the former v2_ prefix for backward compatibility.

Bits are written least-significant-bit first, with canonical zero padding to the last byte. The 24-bit header contains framework (2), light/dark mode (1), long-form/custom-font/theme-toggle flags (3), font (3), semantic-presence (1), easing (2), chroma scaling (2), code-theme index (4), and reserved zero bits (6). Each of the three shades has one default-presence bit and, when changed, a four-bit index. A 56-bit numeric presence mask follows (24 bits without semantic colors), then only changed numeric values in INIT_NUMERIC_FIELDS order. Redundant default overrides, invalid enums, reserved bits, and alternative numeric encodings are rejected by canonical re-encoding. Defaults are snapshotted in init-config-defaults.ts independently of website preset changes.

Bounded stepped controls use minimum-offset integers in the minimum fixed bit width. Header/body scales use 0.01 steps from 0.5 to 1; font-size minima use 0.05px from 10 to 18; mono size/weight scales use 0.01 from 0.8 to 1.2; mono tracking uses 0.05 from 0 to 3.5; mono line height uses 0.01 from 1 to 2. Radius uses 0.1 from 0 to 1.5; border width uses 0.5 from 0 to 4; spacing uses 0.05 from 0.75 to 1.25. Global lightness uses 0.001 from -0.015 to 0.015; chroma boost uses 0.05 from 0.7 to 1.5. Floating-point step arithmetic is normalized within 1e-9; values between steps are rejected. These domains require at most eight bits per control, so byte varints cannot improve them.

Color source domains are lightness 0–1, chroma/chroma limit 0–0.4, hue 0–360. Their compact grids are 0.001, 0.001, and 0.1 respectively. Unlike the bounded sliders, color text entry and semantic swatches can produce finer or fractional values (for example 120 + 40/6). A per-present-color-number bit selects the compact grid or an exact little-endian IEEE-754 binary64 value. This avoids silently changing the website output. Non-finite/out-of-domain values are always rejected. Shade indexes refer to 50,100,200,300,400,500,600,700,800,900,950. Hue-range labels and syntax variation are not generated initialization output and are not encoded. Shade selections and the selected code-theme enum are preserved even though the existing initialization color generator does not derive palette values from them. Only known shared easing/scaling functions can be converted to source enums; arbitrary callbacks are rejected.

Measurements, including framing and Base64URL: default Next.js 27 characters (budget 32); default Vite 27 (32); all optional features 27 (32); customized semantic theme 64 (80); worst-case exact-precision source 498 (504). Deflate produces 28, 28, 28, 76, and 512 respectively. V2 therefore deliberately has no compression codec or decompression attack surface. The worst case contains 42 independent exact color numbers, whose binary64 representations alone take 2688 bits (448 Base64 characters before other fields). A universal 400-character budget would require restricting source precision or losing information. Runtime limits are 1024 encoded characters and 640 binary bytes, with substantially tighter fixture budgets enforced by tests.

V1 remains offline-decodable with its original deflate/JSON/CSS representation and numeric bounds. Its limits remain 32768 encoded characters and 128000 decompressed bytes; decompression is now bounded while streaming, and Base64URL must be canonical. V2 is the only newly emitted format. Unknown versions fail explicitly. V1 can preserve CSS that has no reversible source representation, so there is no lossy automatic v1-to-v2 migration. Preserve v2 defaults, field order, enum order, and generation semantics when adding a future schema.

The registry init-generation directory owns the runtime-neutral color, theme, typography, layout and theme-toggle generators. Website modules re-export them. The CLI validates v2 source again at the generation boundary and uses the same functions. Typography variables precede the static reading-surface template in @layer theme. A template-parity test guards the existing offline CLI template against the website's typography.css. Globals now use the website's complete typography/radius/border/spacing formulas instead of the former CLI approximations. Optional files/imports/dependencies follow the effective CLI options. Project paths are still detected locally. Astro IDs decode, but CLI initialization rejects Astro unless the user explicitly overrides the framework to a supported target; Astro is never implicitly relabeled.
